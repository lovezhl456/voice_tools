## 已修复问题

| 问题 | 影响 | 修复 |
|---|---|---|
| 单条 FS 事件损坏影响整个文件 | 无效时间、schema 等可能使索引回滚同文件里所有正常 FS 映射，导致本应匹配的通话消失 | 逐条校验并保留 FS 白名单字段；坏行、无效 UTF-8、过长行汇总为 gap，保留其他有效观测并标 partial |
| ZIP 有摘要但会话语义不一致 | 可能接受虚假的导出数量、没有 PCAP 的会话、内外清单 Call-ID 不一致的包 | 核对 matched/exported/omitted、每会话 PCAP 和 session.json、内外身份与摘要、完整状态和 partial 证据 |
| 下载未绑定原号码条件 | 同主机上内容有效但属于另一组筛选条件的包可能被接受 | 将本地 job、远端回执和 ZIP 中的号码条件一起比对；恢复旧 job 时从顶层 selection 补齐 |
| 清单类型错误突破主机隔离 | 清单为数组等无效格式会引发未处理异常，使多机汇总中止 | 明确结构校验并返回该主机失败，其他主机结果继续保留 |
| 服务端与客户端额度不一致 | 服务器可能完成一个超过客户端下载条目/清单上限的包，最后整包被拒绝 | 写入每个会话前检查总条目、清单和单会话元数据额度；超限停止追加，交付此前完成的会话并标 partial |
| 子进程零退出码不代表打包成功 | 子进程没有写出最终回执时，客户端会一直等到总超时 | 必须有 complete/partial 状态及 archive 回执，否则立即标失败 |
| Ctrl+C 无法及时取消下载 | 线程池仍等 SCP 最长 300 秒；传输父进程结束后，SSH 子进程也可能继续占用管道 | 号码下载监听停止事件，结束本次本地传输进程组并回收管道，保留远端文件 |
| 恢复任务中的时限未经完整校验 | 损坏或手工改错的 seconds 可产生超长等待 | 远端操作前校验采集时限、处理时限和字节额度 |

## 额度和失败证据

每包最多 50000 个条目，总清单最多 4 MiB，单会话清单最多 16 MiB。超过总条目或清单额度时保留已完成会话；单会话清单过大时记录该会话错误。为后续错误摘要预留空间，最多保存 64 条详细导出错误，`error_count` 保留总数，`omitted_sessions` 保留未导出会话数。源 PCAP 和远端索引继续保留。

压缩包结构校验不替代媒体归属判断。号码方向仍依据 FS 角色或初始 INVITE，媒体按已观测阶段选择。缺失信令、NAT/端口复用、B2BUA 及 FS-only 场景仍可能缺少关联证据；没有 SDP 的 FS 四元组也不能证明已包含独立 RTCP 端口。不会把这些限制描述为完整通话或确定根因。
