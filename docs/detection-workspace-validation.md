使用 `code-readability` 检查相对最新 `origin/main` 的最终代码及 `store`、报告与编辑器调用点。将工作区服务、人工标准／比较和页面职责分开，复用原检测引擎、事务复核和共享波形。整理报告查询条件、返回链接和标准解码，避免复杂条件拼接与重复解析；没有扩展无关模块重构。

### 相同历史负载的刷新比较

使用 `scripts/benchmark_workspace_state.py`，同一 SQLite 数据集包含 6 个固定集（每集 10,000 条标准）、6 份对比（每份 10,000 条录音明细）；相同机器、Python 3.12、5 次刷新，均开启 `tracemalloc` 并将返回值 JSON 序列化。仅切换基线与修复后的产品源码。

| 指标 | 审查基线 | 修复后 |
|---|---:|---:|
| 刷新耗时中位数 | 1.8920 秒 | 0.00120 秒 |
| Python 峰值分配 | 170,787,280 字节 | 29,369 字节 |
| 响应体 | 4,589 字节 | 4,703 字节 |

修复后旧库首次启动摘要回填用时 0.331 秒，之后刷新不再付出完整历史解码成本。响应增加的是样本集创建时间；完整明细仍按需可读。峰值是 Python 分配量而非进程 RSS，耗时包含内存追踪开销。此结果仅证明固定集／对比历史占主导的合成负载改善，不证明实际大录音库或生产服务容量。
