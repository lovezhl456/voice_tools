# 复核能力基线与交付证据

修改复核流程时，先对照下表记录“保留／增强／移除”。整通汇总改变结论粒度，波形、定位、筛选、试听和标签交接仍须保留。移除能力应明确用户影响及授权来源；不能仅删掉断言使检查变绿。

## 必须保留的用户流程

可执行用例在 [review.spec.cjs](../tests/browser/review.spec.cjs)，标题以 R01–R08 对应本表。默认运行必须覆盖每项的桌面与手机视口；缺项目、缺能力、空测试、跳过或失败都不能通过运行器的完整验收。

| 编号 | 旧入口与新入口应保留的能力 | 实际验证 |
|---|---|---|
| R01 | 目录选择、文件／路径多关键词检索与队列筛选 | 从夹具导航进入报告，切换全部／例外／通过集合，大小写混合检索，目录与状态组合 |
| R02 | 波形、时间轴、左右轨及角色提示 | 检查实际画布像素；缩放、显示增益、键盘／拖动边界、范围聚焦和点击定位；手机无横向溢出 |
| R03 | 定位、区间试听、音量／静音，单轨试听仍保留双轨图 | 建议范围同步播放器，播放中切换声道，音量／静音保留；取消循环到点暂停，循环发生实际时间跳转 |
| R04 | 标注草稿保护、一次填写整通、完整 CSV 交接 | 筛选不丢草稿，保存后移出队列，导出全部记录，安装包 CLI 校验，再打开导入；错误身份不覆盖已有标签 |
| R05 | 矛盾或不足证据不能自动放行 | 模型误报、跨用户边界旧输出、未知角色仍在例外队列；快速切换录音不会残留上一通 |
| R06 | 缺素材／旧结果可解释地退化 | 无音频仍有图、禁用播放；旧无摘要仍可播放；缺角色元数据不标为已核实；单声道不冒认双方；坏文件不残留音频；空窗口及容差内微小越界仍可试听 |
| R07 | 跨机结果带回后的可复核性 | 真正打包、执行、收集、重建，从任务总览进入人工标签页，查看嵌入波形并播放校验后的包内音频 |
| R08 | 原逐轮及输出间隙复核入口 | 两个旧入口都检查共享波形与播放器，避免新页面接入破坏原有入口 |

每例还会拒绝浏览器运行错误、控制台错误及非本机依赖请求。截图保留的是实际界面；自动化覆盖这些约定，不替代视觉改版时查看截图和核对信息层级。

## 必须拒绝的判断

以下拒绝条件优先由安装包 E2E 验证。R05 的[夹具生成器](../tests/browser/generate_fixtures.py)执行实际安装包的整通分析，先断言模型冲突与旧输出均为 `NEEDS_REVIEW`，再由[浏览器 R05](../tests/browser/review.spec.cjs)验证例外队列及原因；并非只展示手工写好的结论。未被该输入覆盖的时序／任务失败仍由 [test_assessment.py](../tests/recording_qa/test_assessment.py) 和 [test_assessment_delivery.py](../tests/recording_qa/test_assessment_delivery.py) 补充。

| 条件 | 不允许的结果 | 必须验证 |
|---|---|---|
| 模型说有回答，工程活动不支持或只出现在其他时段 | 自动通过 | 安装包夹具 `model_conflict` 与浏览器 R05 验证活动不足；`test_engineering_support_must_overlap_the_model_response` 补充不重叠时段 |
| AI 早于用户结束已经开始输出 | 当作零延迟的新回答 | 安装包夹具 `old_output` 与浏览器 R05 验证待复核及原因；其后确有新回答仍单独评估 |
| 模型起点较早，实际声学支持迟到 | 隐藏迟答 | `test_model_onset_cannot_hide_late_engineering_evidence` |
| 声道／接管范围未知、观察不足、模型未完整执行 | 自动通过 | 已有未知角色、短窗口、模型失败／覆盖不足回归 |
| 无应答／迟答证据已充分，但后面还有很长录音 | 整段剩余录音都成为建议试听范围 | `test_response_findings_stop_at_deadline_or_response_not_recording_end` |
| 模型 doctor 未就绪或返回无效结果 | 当作普通 findings 继续依赖步骤 | 实际任务验证 `failed / skipped / completed`，独立步骤仍执行 |
| 导入错误身份或无效波形摘要 | 静默接收／覆盖标签 | CSV 身份回归、波形边界回归与 R04 |

## 可复现验收

使用[测试指南](testing.md#安装包浏览器验收)的准备命令，然后从仓库根目录运行：

```bash
python scripts/check_review.py
```

仅复查上述模型冲突和旧输出时可运行 `python scripts/check_review.py --grep R05 --out .artifacts/review-r05`（使用新目录）。产物中的 `site/main/assessment.jsonl` 保存实际分析结论，`browser-results.json` 保存桌面／手机的 R05 断言结果；全量验收仍执行不带 `--grep` 的命令。

它构建一次 wheel、安装到独立目录、确认导入来源、生成确定性合成音频和模拟模型证据，启动带音频字节范围支持的临时本机服务，执行两种视口，最后关闭服务。无需本机 8080、个人录音、系统 TTS、GPU 或模型权重；测试不会安装产品可选模型。

`verification.json` 记录提交／工作区状态、wheel SHA-256、环境、命令、能力覆盖及结果。完整通过须 `status=passed` 且 `coverage=full_baseline`，desktop/mobile 均有 R01–R08。`--grep`／`--project` 只做选测，记录为 `selected_cases`，不能宣称完整验收。失败日志、截图和 trace 保留供核对。

GitHub `Review acceptance` 的[待启用配置](examples/review-acceptance.yml)已准备：启用后在 PR 和 main 更新时执行规则回归与同一浏览器命令，上传 7 天有效的证据。当前推送凭据缺少 `workflow` 权限，因此只提交配置示例，尚未部署或运行 GitHub CI。工作流计划使用只读仓库权限，无部署和外部业务调用；本次不改变分支保护设置，自动检查状态与平台是否强制要求该状态是两件事。

## 交付时怎么说

按 [PR 模板](../.github/PULL_REQUEST_TEMPLATE.md) 记录实际用户结果、保留能力、拒绝条件和各层证据。至少区分：

- 自动规则／协议回归：证明选定分支与合同的行为。
- 安装包、页面与交互：证明用户拿到的产物可执行且能力保留。
- 真实模型／设备：需独立运行，不能用确定性模拟模型代替。
- 生产样本：真实误报、漏检和节省人工时间需要代表性录音及人工真值。

新失败或未执行的必需项必须明确记录；上一层通过不自动证明下一层通过。
